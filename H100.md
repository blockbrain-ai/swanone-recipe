# Running swanOne on an H100 NVL

The complete route on one x86 NVIDIA H100 NVL (94 GB), from an empty pod to JevBench's harness. The serve
command is the one in JevBench issue #23, §4.2, with two flags changed: `--max-model-len` 4096 → 16384, and
`--host` 0.0.0.0 → 127.0.0.1.

**What was measured on an H100 NVL (95,830 MiB) at `--gpu-memory-utilization 0.90`:** with only
`--max-model-len` changed, caps of 4096, 8192 and 16384 each started, with the same ~7.96 GiB of KV cache; a
larger cap lowers the number of requests that fit at once, which a serial run does not use. At 8192 and at
16384 the server answered a long-policy test prompt of about 6,360 tokens with the expected label and one
output token. At 16384 it answered its first request about 20 minutes after launch, the checkpoint download
included (one measurement, 2026-09-22).

## What you need

- **An H100 NVL (94 GB).** That is the card measured here; JevBench's own round-4 run of swanOne used an H200
  (141 GB). The image's amd64 build is compiled for `sm_75`, `sm_80`, `sm_86`, `sm_90`, `sm_100` and
  `sm_120`, not `sm_103`, so a B300 or GB300 will fail. An 80 GB H100 runs out of memory while the NVFP4
  weights are repacked, before any KV cache is allocated.
- **`--gpu-memory-utilization 0.90`.** At 0.786 a 94 GB card has no memory left for the KV cache.
- **Docker with the NVIDIA runtime**, or a host that runs the image directly (see the notes under step 1).
- **This repository** on the host, and at least 115 GB of free disk for the 99 GiB checkpoint and the 8.6 GB
  image alone; leave room beyond that for Docker and caches.

## 1. Serve the model

Set the four directories first. A literal paste of an angle-bracket placeholder fails, because `<` is a shell
redirect.

```bash
export PATCHDIR=/srv/swanone-recipe/patches     # this repository's patches/
export ASSETDIR=/srv/swanone-recipe/assets      # this repository's assets/
export HFCACHE=/srv/hf                          # a Hugging Face cache; the weights download into it
export PLECACHE=/srv/ple                        # a directory for the PLE cache; may be empty
```

```bash
docker run --gpus all --network host --ipc=host \
  -v $PATCHDIR/ple_layer_patched.py:/usr/local/lib/python3.12/dist-packages/vllm/models/qwen3_8_flash_next/nvidia/ple_layer.py \
  -v $PATCHDIR/qsa_ops_patched.py:/usr/local/lib/python3.12/dist-packages/vllm/models/qwen3_8_flash_next/nvidia/ops/qsa.py \
  -v $PATCHDIR/qsa_nvidia_patched.py:/usr/local/lib/python3.12/dist-packages/vllm/models/qwen3_8_flash_next/nvidia/qsa.py \
  -v $PATCHDIR/mtp_patched.py:/usr/local/lib/python3.12/dist-packages/vllm/models/qwen3_8_flash_next/nvidia/mtp.py \
  -v $PATCHDIR/modelopt_patched.py:/usr/local/lib/python3.12/dist-packages/vllm/model_executor/layers/quantization/modelopt.py \
  -v $PATCHDIR/ple_offload/ple_offload_layer.py:/usr/local/lib/python3.12/dist-packages/vllm/model_executor/layers/ple_offload_layer.py \
  -v $PATCHDIR/ple_offload/worker.py:/usr/local/lib/python3.12/dist-packages/vllm/v1/ple_offload/worker.py \
  -v $PATCHDIR/ple_offload/connector.py:/usr/local/lib/python3.12/dist-packages/vllm/v1/ple_offload/connector.py \
  -v $PATCHDIR/ple_offload/protocol.py:/usr/local/lib/python3.12/dist-packages/vllm/v1/ple_offload/protocol.py \
  -v $HFCACHE:/root/.cache/huggingface \
  -v $PLECACHE:/root/.cache/vllm \
  -v $ASSETDIR/draft_vocab_en_code_47k.txt:/root/draft_vocab.txt \
  -e VLLM_PLE_CPU_OFFLOAD=1 \
  -e VLLM_USE_V2_MODEL_RUNNER=1 \
  -e VLLM_PLE_OFFLOAD_STEP_TIMEOUT=300 \
  -e VLLM_MTP_DRAFT_VOCAB=/root/draft_vocab.txt \
  -e HF_HOME=/root/.cache/huggingface \
  vllm/vllm-openai:qwen38-flash-next@sha256:0aea30240f3e3d9ffae8526643950e170eb5fa07fc427016a9dd90892afa2aa3 \
  Mia-AiLab/Qwen3.8-Flash-Next-NVFP4 \
  --revision 925d7be6c14c6c9442ef83e8f05b5a3c39304f69 \
  --served-model-name swanone \
  --tensor-parallel-size 1 \
  --gpu-memory-utilization 0.90 \
  --max-model-len 16384 \
  --kv-cache-dtype fp8 \
  --mamba-ssm-cache-dtype bfloat16 \
  --max-num-seqs 8 \
  --max-num-batched-tokens 2048 \
  --enable-chunked-prefill \
  --load-format safetensors \
  --safetensors-load-strategy lazy \
  --distributed-executor-backend mp \
  --speculative-config '{"method":"mtp","num_speculative_tokens":3,"use_local_argmax_reduction":true}' \
  --compilation-config '{"mode":0,"cudagraph_mode":"FULL_DECODE_ONLY","cudagraph_capture_sizes":[4,8,12,16,20,24,28,32]}' \
  --reasoning-parser qwen3 \
  --enable-auto-tool-choice --tool-call-parser qwen3_coder \
  --enable-prompt-tokens-details \
  --host 127.0.0.1 --port 8890
```

- **The nine `-v` patch mounts** put MiaAI Lab's patch output (`patches/`, see `patches/MANIFEST.md` for each
  file's target and sha256) over the image's own files. The four `ple_offload` files are in a subdirectory.
- **Without Docker `-v`** (a pod that runs the image itself): copy the nine files over the same absolute
  paths, copy the asset to `/root/draft_vocab.txt`, and export the five `-e` variables. Nothing else changes.
- **The image's entrypoint is `vllm serve`, and it has no `CMD`.** A host setting that overrides the command
  (RunPod's start command, for example) produces `vllm serve <your command>` and exits. Override the
  entrypoint instead.
- **`VLLM_PLE_CPU_OFFLOAD=1` is required**; it turns the offload on.
- **`--revision` pins the weights** that the published numbers describe.
- **On the first start, do not set `HF_HUB_OFFLINE=1`**, or the weights will not download.
- **`VLLM_PLE_PACKED_TABLE_DIR` is deliberately not set**; without a packed table the patch loads the PLE
  shards into RAM, which is how the H100 NVL runs above were served.
- **MTP is a speed feature.** To run without it, drop `--speculative-config`, `-e VLLM_MTP_DRAFT_VOCAB` and
  the `draft_vocab` mount; nothing else changes.
- **`--host 127.0.0.1` keeps the server, which has no API key, off the network.** With `--network host`,
  `0.0.0.0` would expose it on every interface of the machine. The measured runs bound `0.0.0.0`; the shim
  connects over loopback either way, so nothing else changes.

## 2. Start the shim, on the same machine

```bash
SHIM_VLLM=http://127.0.0.1:8890/v1/chat/completions SHIM_MODEL=swanone SHIM_PORT=8009 \
python3 shim/typesafe_native_shim.py
```

The shim binds `127.0.0.1` only, so the harness must run on the same machine. `SHIM_MODEL` must match
`--served-model-name`. Before answering, the shim reads the served model's `max_model_len` from vLLM and logs
it; if the server does not list `SHIM_MODEL`, reports no limit, or was started with less than 4096
(`SHIM_MIN_CONTEXT`), it answers 503 to every request, so a misconfigured server stops the run instead of
scoring it.

## 3. Warm up

The first request compiles kernels:

```bash
curl -s http://127.0.0.1:8009/v1/systemone -H 'Content-Type: application/json' -d '{"state": "warm-up",
  "questions": {"decision": {"type": "noul", "instructions": "Is this a warm-up?",
  "criteria": {"true": "yes", "false": "no"}}}}'
```

The reply carries `"usage": {..., "completion_tokens": 1, ...}`. **Start the run only once this returns HTTP
200.** The warm-up is also when the shim reads the server's context limit; while vLLM is still loading it
answers 502, and a 503 names what is misconfigured.

## 4. Run the harness

The command under "Step 4" in the [README](README.md), with `--endpoint http://127.0.0.1:8009`.

**What the shim answers to an input it cannot take:** a prompt over the server's context limit, more than 26
options, or a question type it does not know gets HTTP 422, which JevBench's runner scores as one wrong
answer and moves past. vLLM's own 401, 403 and 429 pass through unchanged, and any other vLLM failure is a
502; those count toward the runner's rule that three consecutive failures stop the run.
`python3 shim/test_shim.py` checks all of this without a GPU.
